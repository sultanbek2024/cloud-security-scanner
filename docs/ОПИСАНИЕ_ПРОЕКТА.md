# Cloud Scanner — Описание проекта и техническая документация

Данный документ предназначен для соавторов, научных руководителей и рецензентов, работающих над пояснительной запиской к дипломному проекту. В документе подробно изложены архитектурные решения, математическая модель скоринга, спецификация всех проверок безопасности и руководство по эксплуатации.

---

## 1. Цель системы

**Cloud Scanner** — это специализированное программное средство (инструмент статического аудита конфигураций — Cloud Security Posture Management / CSPM) для автоматизированного анализа облачной инфраструктуры Amazon Web Services (AWS) на предмет уязвимостей, ошибок конфигурации (misconfigurations) и отклонений от признанных международных стандартов безопасности.

**Основные цели проекта:**
1. **Автоматизация аудита безопасности**: выявление критических брешей в сетевом периметре, управлении доступом (IAM), хранилищах данных (S3, EBS), базах данных (RDS) и журнальном аудите (CloudTrail).
2. **Оценка соответствия стандарту CIS AWS Foundations Benchmark**: привязка каждого правила к рекомендациям международного Центра интернет-безопасности (CIS) версий v1.4 и v3.0.
3. **Объективная квантитативная оценка (Security Score)**: математический расчет индекса защищенности инфраструктуры в диапазоне от 0 до 100 баллов с присвоением буквенного рейтинга (A, B, C, D, F).
4. **Формирование понятной отчетности**: генерация структурированного интерактивного отчета в формате HTML (для инженеров и руководства) и экспорта в JSON (для интеграции в CI/CD пайплайны DevSecOps).
5. **Поддержка государственного языка**: интерфейс отчетов, консольные уведомления и рекомендации по устранению сформулированы на казахском языке, что обеспечивает актуальность для казахстанского государственного и корпоративного секторов.

## 2. Архитектура и модули системы

├── checks/                     # Модули проверок по сервисам AWS

### Назначение модулей простыми словами:

- **Точка входа (`scanner.py`)**: консольная утилита на базе встроенного модуля `argparse`. Принимает аргументы командной строки: параметры аутентификации AWS, кастомный эндпоинт (для локальных эмуляторов `moto_server` / LocalStack), целевой регион сканирования, флаг сканирования всех регионов (`--all-regions`) и путь для сохранения отчета.
- **Модели данных (`core/models.py`)**:
  - `Severity` — перечисление уровней опасности: `CRITICAL` (вес 10), `HIGH` (вес 7), `MEDIUM` (вес 4), `LOW` (вес 1).
  - `Finding` — dataclass, описывающий выявленную проблему: идентификатор правила (`rule_id`), заголовок (`title`), целевой ресурс (`resource`), уровень опасности (`severity`), описание риска (`description`), рекомендация по исправлению (`recommendation`) и ссылка на стандарт (`standard`, например, `CIS AWS 5.2`).
- **Реестр проверок (`core/registry.py`)**: обеспечивает слабую связность (loose coupling) архитектуры. Каждая проверка регистрируется декоратором `@register_check(rule_id, severity, category)`. Реестр позволяет добавлять новые правила без модификации ядра сканера.
- **Движок выполнения (`core/engine.py`)**:
  - Автоматически находит и динамически импортирует все модули из пакета `checks/`.
  - Управляет сессиями `boto3.Session`.
  - Запускает проверки в изолированных блоках `try-except`: сбой в одной проверке (например, из-за нехватки прав IAM к конкретному API) перехватывается, логируется, но не прерывает общее сканирование.
  - Поддерживает мультирегиональное сканирование зависимых сервисов (EC2, RDS) при передаче флага `--all-regions`.
- **Движок скоринга (`core/scoring.py`)**: анализирует список найденных уязвимостей, вычисляет штрафные баллы с учетом затухания повторных находок и нормализует оценку относительно общей емкости правил.
- **Генераторы отчетов (`report/`)**:
  - `html_report.py` внедряет вычисленные метрики в адаптивный HTML-шаблон.
  - `template.html` формирует отчет без внешних CDN-зависимостей: содержит круговую диаграмму/прогресс-бар, карточки статистики по уровням критичности, цветовую индикацию и детальную таблицу с рекомендациями.
  - `json_report.py` сохраняет детальные результаты в стандартизированном формате JSON.

## 4. Математическая модель расчета оценки (Security Score)

Оценка безопасности представляет собой интегральный показатель защищенности облачной среды по 100-балльной шкале.

### 4.1. Весовые коэффициенты критичности
Каждому уровню серьезности уязвимости поставлен в соответствие штрафной вес:
- **CRITICAL**: $W = 10$ баллов
- **HIGH**: $W = 7$ баллов
- **MEDIUM**: $W = 4$ балла
- **LOW**: $W = 1$ балл

### 4.2. Убывающий штраф за повторные ресурсы (Diminishing Penalty)
Если в инфраструктуре обнаружено несколько одинаковых уязвимостей одного типа (например, 10 Security Group с открытым SSH), линейное суммирование штрафов ($10 \times 7 = 70$) привело бы к мгновенному обнулению оценки только из-за одной типовой проблемы конфигурации.

Для решения этой проблемы в проекте реализован алгоритм затухания повторного штрафа:
$$P_r = W_r \times \left(1 + 0.25 \times \min(n - 1, 4)\right)$$
где:
- $W_r$ — базовый вес правила;
- $n$ — количество ресурсов, затронутых данным правилом ($n \ge 1$);
- Каждая дополнительная уязвимость того же типа добавляет **25%** от веса правила;
- Максимальный штраф за одно правило ограничен удвоенным базовым весом ($+100\%$ при $n \ge 5$).

### 4.3. Емкость шкалы (Capacity)
Емкость штрафной шкалы $C$ динамически рассчитывается как **сумма весов всех зарегистрированных правил**:
$$C = \sum_{r \in \text{Rules}} W_r$$

Для разработанных 15 правил:
$$C = (3 \times 10) + (5 \times 7) + (4 \times 4) + (3 \times 1) = 30 + 35 + 16 + 3 = 84$$

**Теоретическое обоснование:**
- Если в инфраструктуре допущено нарушение **каждого** проверенного стандарта безопасности (по 1 ресурсу на каждое правило), суммарный штраф составит ровно $\sum W_r = 84$.
- В этом случае нормализованный штраф составляет ровно $\frac{84}{84} \times 100 = 100\%$, а итоговый балл равен $0/100$.
- Таким образом, оценка не обнуляется от одной изолированной критической ошибки, но адекватно отражает системное несоблюдение стандартов.

### 4.4. Формула итогового балла и грейды
$$\text{Total Penalty} = \sum_{r} P_r$$
$$\text{Normalized Penalty} = \min\left(100.0, \frac{\text{Total Penalty}}{C} \times 100.0\right)$$
$$\text{Score} = \max\left(0, \text{round}(100.0 - \text{Normalized Penalty})\right)$$

Таблица соответствия буквенных рейтингов:
- **A (90 – 100)**: Өте жақсы (Отлично). Высочайший уровень соответствия стандартам CIS.
- **B (75 – 89)**: Жақсы (Хорошо). Инфраструктура надежна, присутствуют незначительные замечания.
- **C (50 – 74)**: Қанағаттанарлық (Удовлетворительно). Требуется плановое устранение рисков.
- **D (25 – 49)**: Нашар (Плохо). Существенные бреши в сетевом периметре или политиках доступа.
- **F (0 – 24)**: Қауіпті (Критично). Инфраструктура крайне уязвима для атак.

### 4.5. Пример практического расчета на тестовом стенде
1. **Стенд ДО устранения уязвимостей:**
   - Обнаружено 17 находок по 14 правилам (открытые порты SG, публичные S3, незашифрованный EBS, пользователи без MFA, root без MFA, устаревшие ключи, wildcard-политика, открытый RDS, отсутствие CloudTrail).
   - Суммарный штраф с учетом затухания повторов: $\text{Total Penalty} = 65.75$.
   - Нормализованный штраф: $\frac{65.75}{84} \times 100\% \approx 78.27\%$.
   - **Итоговая оценка:** $100 - 78 = 22 / 100$ (Грейд: **F, Қауіпті**).
2. **Стенд ПОСЛЕ автоматического исправления (`remediate_env.py`):**
   - Устранены уязвимости по 13 правилам (закрыты порты на приватную сеть `10.0.0.0/8`, пересоздан зашифрованный EBS-том, включены Public Access Block и шифрование S3, настроен CloudTrail, удалена wildcard-политика, создано виртуальное MFA для пользователя).
   - Единственная оставшаяся находка: `IAM-002` (Root-аккаунт без MFA, $W = 10$). Причина: в локальном эмуляторе `moto_server` корневой аккаунт эмулируется со статическим статусом `AccountMFAEnabled=0` и не имеет API-интерфейса для привязки физического MFA-токена.
   - Суммарный штраф: $10.0$.
   - Нормализованный штраф: $\frac{10.0}{84} \times 100\% \approx 11.9\%$.
   - **Итоговая оценка:** $100 - 12 = 88 / 100$ (Грейд: **B, Жақсы**). Рост защищенности: **+66 баллов**.

## 5. Инструкция по запуску и тестированию

### 5.1. Предварительные требования
- Python версии 3.11 или выше.
- Запущенный эмулятор AWS (Moto Server или LocalStack) на `http://localhost:4566`.
- Установленные зависимости: `pip install -r requirements.txt`.

### 5.2. Развертывание тестового уязвимого стенда
Для наполнения эмулятора тестовыми уязвимыми ресурсами (Security Groups, EBS, S3, IAM, RDS):
```powershell
.\venv\Scripts\python.exe scripts\setup_vulnerable_env.py
```
*Для полной очистки тестовых ресурсов предусмотрен флаг:*
```powershell
.\venv\Scripts\python.exe scripts\setup_vulnerable_env.py --cleanup
```

### 5.3. Запуск сканирования
Базовое сканирование целевого региона с формированием интерактивного отчета:
```powershell
.\venv\Scripts\python.exe scanner.py --endpoint-url http://localhost:4566 --output report.html
```
Параллельный экспорт в формат JSON:
```powershell
.\venv\Scripts\python.exe scanner.py --endpoint-url http://localhost:4566 --output report.html --json-output report.json
```
Сканирование всех активных регионов AWS (для реального облака):
```powershell
.\venv\Scripts\python.exe scanner.py --all-regions --output enterprise_report.html
```

### 5.4. Демонстрация полного цикла «до/после» (Run Demo)
Скрипт автоматически сканирует уязвимый стенд, выполняет remediation, сканирует повторно и выводит сравнительную таблицу в консоль:
```powershell
.\venv\Scripts\python.exe scripts\run_demo.py
```

### 5.5. Запуск модульного и интеграционного тестирования
Запуск полного набора автотестов:
```powershell
.\venv\Scripts\python.exe -m pytest
```

| **Pytest** | Фреймворк тестирования | Стандарт де-факто для Python: лаконичный синтаксис фикстур, подробные трассировки ошибок, удобная параметризация тестов. |
| **Moto** | Библиотека мокирования AWS | Позволяет выполнять полное функциональное тестирование всех 15 проверок безопасности локально в оперативной памяти или через `moto_server`, гарантируя 100% изоляцию без финансовых затрат на аренду реального облака AWS. |
| **CLI интерфейс (argparse)** | Форм-фактор приложения | Инструменты аудита безопасности облачной инфраструктуры в корпоративной среде используются SecOps-инженерами и встраиваются в конвейеры непрерывной интеграции (CI/CD Pipelines). CLI обеспечивает мгновенный запуск в Docker-контейнерах, отсутствие накладных расходов на веб-сервер и возможность блокировать пайплайны по коду возврата. |

## 7. Ограничения системы и перспективы развития

### Текущие ограничения:
1. **Один облачный провайдер**: поддержка аудита реализована исключительно для платформы AWS.
2. **Ограничения эмулятора Moto**: локальный эмулятор `moto_server` не реализует закрытые внутренние API Amazon (например, аппаратную привязку U2F/MFA для корневого пользователя root).
3. **Статический анализ метаданных**: сканер анализирует конфигурационные манифесты и метаданные API, не выполняя глубокий анализ трафика (Deep Packet Inspection / VPC Flow Logs).

### Перспективы дальнейшего развития:
1. **Мультиоблачность (Multi-Cloud CSPM)**: расширение архитектуры для поддержки Microsoft Azure и Google Cloud Platform (GCP).
2. **Расширение базы проверок**: добавление проверок управляемых кластеров Kubernetes (Amazon EKS), бессерверных функций (AWS Lambda), шлюзов API (API Gateway) и секретов (AWS Secrets Manager).
3. **Автоматическое исправление в один клик (Auto-Remediation CLI)**: добавление флага `--auto-fix` непосредственно в CLI-сканер для устранения типовых уязвимостей (закрытие портов, включение шифрования) на основе политик безопасности.
4. **Интеграция с корпоративными SIEM/SOAR**: разработка модулей отправки событий в Splunk, Wazuh, Elastic Security и отправка алертов в Telegram/Slack.

## 8. Описание файлов проекта

- `scanner.py` — Точка входа в консольное приложение, разбор аргументов CLI и запуск процесса сканирования.
- `core/models.py` — Определение базовых структур данных: класса уязвимости `Finding` и перечисления уровней опасности `Severity`.
- `core/registry.py` — Декоратор `@register_check` и центральный реестр метаданных всех проверок безопасности.
- `core/engine.py` — Исполнительный движок, отвечающий за поиск проверок, вызов API AWS и изоляцию исключений.
- `core/scoring.py` — Математический модуль расчета итоговой оценки (0-100), штрафных весов и буквенного грейда.
- `checks/ec2.py` — Проверки открытых портов SSH (22), RDP (3389), произвольных портов (0.0.0.0/0) и шифрования EBS-томов.
- `checks/s3.py` — Проверки публичного доступа (PAB), шифрования по умолчанию и версионирования бакетов S3.
- `checks/iam.py` — Проверки пользователей без MFA, root-аккаунта, ротации access key, wildcard-политик и сложности паролей.
- `checks/rds.py` — Проверка публичной доступности экземпляров реляционных баз данных Amazon RDS.
- `checks/cloudtrail.py` — Проверки наличия активного трейла CloudTrail и включения валидации целостности логов.
- `report/html_report.py` — Сборка контекста и рендеринг итогового HTML-отчета с помощью Jinja2.
- `report/json_report.py` — Экспорт обнаруженных уязвимостей и сводной статистики в машиночитаемый формат JSON.
- `report/template.html` — Адаптивный HTML5-шаблон отчета с карточками статистики, диаграммой и казахским интерфейсом.
- `scripts/setup_vulnerable_env.py` — Скрипт развертывания уязвимой инфраструктуры на стенде эмулятора AWS с флагом `--cleanup`.
- `scripts/remediate_env.py` — Скрипт автоматического устранения выявленных уязвимостей на тестовом стенде.
- `scripts/run_demo.py` — Сценарий сквозной демонстрации «до/после» со сканированием, исправлением и наглядным сравнением.
- `tests/test_scoring.py` — Модульные тесты математической модели скоринга, штрафных весов и емкости шкалы.
- `tests/test_engine.py` — Тесты механизма обнаружения проверок и устойчивости к исключениям.
- `tests/test_ec2_checks.py` — Модульные тесты проверок сетевой безопасности EC2 и дисков EBS на моках `moto`.
- `tests/test_s3_checks.py` — Модульные тесты проверок безопасности объектных хранилищ S3 на моках `moto`.
- `tests/test_iam_checks.py` — Модульные тесты политик, учетных записей и ключей IAM на моках `moto`.
- `tests/test_rds_checks.py` — Модульные тесты проверки публичности баз данных RDS на моках `moto`.
- `tests/test_cloudtrail_checks.py` — Модульные тесты проверок журнала аудита CloudTrail на моках `moto`.
- `requirements.txt` — Список внешних библиотек и зависимостей проекта.
- `README.md` — Стартовая инструкция пользователя по установке, настройке и запуску сканера.
